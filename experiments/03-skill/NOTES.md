# 실험 03: 스킬 (반복 작업을 SKILL.md로 패키징)

스킬: `.claude/skills/meeting-summary/SKILL.md`
역할: 회의 메모를 `결정사항 / 할 일(표) / 미해결 질문 / 한 줄 요약` 4단 형식으로 고정 출력.
입력: `memo1.txt`, `memo2.txt` (회의 메모 예시, 파이썬 아님)

## 실행한 것

| 파일 | 조건 |
|---|---|
| `result-skill-1.md` | `/meeting-summary` + memo1 (스킬 직접 호출) |
| `result-skill-2.md` | `/meeting-summary` + memo2 (다른 입력에도 같은 형식인지) |
| `result-noskill-1.md` | 일반 요청 "요약해줘" + memo1, 프로젝트 안에서 실행 |
| `result-baseline-1.md` | 일반 요청 "요약해줘" + memo1, **프로젝트 밖**에서 실행 (진짜 기준선) |

## 결과 비교

| 항목 | 스킬 호출 | 기준선 (스킬 없음) |
|---|---|---|
| 섹션 제목 | 4개 고정 | 제목 임의 (확정 사항 / 액션 아이템 / 미결 사항) |
| 할 일 표현 | 표 (담당/할 일/기한) | 글머리 기호 |
| 한 줄 요약 | 있음 | 없음 |
| 불필요한 부연 | 없음 | "다음 회의 안건으로 올리는 것을 권장합니다" 추가 |
| 다른 입력(memo2) | 같은 4단 형식 유지 | 해당 없음 |

## 중요한 발견: 스킬은 자동으로 불려 온다
- `result-noskill-1`은 스킬을 부르지 않았는데도 스킬 결과와 형식이 같았다.
- 이유: SKILL.md의 `description`에 "회의록, 요약을 요청할 때 사용"이라고 적어 두었기 때문에, 모델이 일반 요약 요청에서도 스킬을 스스로 골랐다.
- 그래서 기준선은 프로젝트 밖(스킬이 없는 위치)에서 다시 만들어야 했다.
- 교훈: `description`은 스킬의 "호출 조건"이다. 너무 넓게 쓰면 의도하지 않은 곳에서 발동하고, 너무 좁게 쓰면 안 불린다.

## 한계
- 각 조건 1회 실행. `result-noskill-1`이 정말 자동 호출 때문인지는 호출 로그로 확인하지 않았고, 형식 일치로 추정한 것이다.

## 결론
- 스킬 = 반복 작업의 형식과 규칙을 파일 하나로 고정하는 방법. 매번 같은 지시를 쓰지 않아도 된다.
- 필요할 때만 로드되므로 `CLAUDE.md`(항상 로드)와 역할이 다르다.
