# 실험 02: 컨텍스트 엔지니어링 (CLAUDE.md 유무 비교)

같은 지시 한 줄("문자열이 팰린드롬인지 확인하는 함수 만들어줘. 파일은 만들지 말고 답변으로만 보여줘.")을
`with/`(CLAUDE.md 있음)와 `without/`(없음) 폴더에서 각각 `claude -p`로 실행.
상위 폴더와 사용자 홈에 다른 CLAUDE.md가 없는 것을 확인하고 실행함.

## CLAUDE.md 규칙 6개 vs 결과

| 규칙 | with | without |
|---|---|---|
| 답변을 `[확인]` 한 줄로 시작 | 지킴 | 안 지킴 ("Python 예시입니다.") |
| 표준 라이브러리만 사용 | 일부 위반 (아래 참고) | 해당 없음 |
| 함수에 타입 힌트 + 한 줄 docstring | 지킴 | 타입 힌트만, docstring 없음 |
| pytest 테스트 동봉 | 지킴 (5건) | 안 지킴 (print 예시만) |
| 설명 2줄 이내 | 지킴 (문장 2개) | 안 지킴 (3항목 + 후속 제안) |
| 마지막 줄 `다음 단계 제안:` | 지킴 | 안 지킴 |

## 관찰
- 프롬프트는 한 줄 그대로인데 `CLAUDE.md` 하나로 형식, 테스트, 문체가 모두 바뀌었다. 매번 지시에 반복해 쓸 필요가 없다.
- **규칙끼리 충돌**: "외부 패키지 금지"와 "pytest로 테스트"는 모순이다(pytest는 외부 패키지). 모델은 `import pytest`를 쓰면서도 "표준 라이브러리(`re`)만 사용했고"라고 답했다. 규칙이 모순되면 모델이 조용히 한쪽을 골라 버린다.
- 사소한 불일치: docstring은 "영문자와 숫자만"이라 했는데 정규식에는 한글이 포함됨.
- 한계: 1회 실행 결과다. 응답은 매번 달라질 수 있어 확실하게 하려면 여러 번 반복해야 한다.

## 결론 (CLAUDE.md 작성 원칙)
- 검증 가능한 문장으로 쓴다 (시작 문구, 마지막 줄 문구처럼).
- 규칙끼리 모순이 없는지 확인한다.
- 항상 적용할 것만 적는다. 한 번만 필요한 지시는 프롬프트에 쓴다.
