# 실험 04: 서브에이전트 (리뷰어)

에이전트: `.claude/agents/reviewer.md`
- `tools: Read, Grep, Glob` (읽기 전용. Edit, Write, Bash 없음)
- 출력 형식 고정: 심각도 높음 / 낮음 / 놓친 테스트 / 한 줄 판정

## 실험 A: 리뷰 실행 (`result-review.md`)
`sandbox/phone/phone.py`(1단계에서 pytest 13개를 통과한 코드)를 reviewer에게 리뷰시킴.

리뷰어의 주요 지적을 직접 실행해 확인한 결과:

| 입력 | 결과 | 리뷰어 지적 |
|---|---|---|
| `82 10 1234 5678` | `None` | 맞음 (주석은 82도 처리한다고 했지만 `+`일 때만 변환) |
| `+82 010-1234-5678` | `None` | 맞음 |
| `010+1234+5678` | `010-1234-5678` | 맞음 (잘못된 구분자가 통과) |
| `((010)1234-5678` | `010-1234-5678` | 맞음 (괄호 짝 검증 없음) |
| `010\n1234\n5678` | `010-1234-5678` | 맞음 (개행 허용) |
| 전각 숫자 | 확인 못 함 | 내 확인 스크립트가 터미널 인코딩 때문에 입력을 깨뜨림. 보류 |

- 테스트 13개가 모두 통과해도 코드에는 구멍이 있었다. **통과한 테스트 ≠ 올바른 코드**이고, 별도 관점의 리뷰가 이를 찾아냈다.
- 리뷰어는 "코드를 실행해 확인한 것은 아니고 코드상 추론", "테스트 파일은 읽지 않아 확인 못 함"처럼 한계를 스스로 밝혔다 (프롬프트에서 추측 금지를 지시한 효과).

## 실험 B: 컨텍스트 분리
- 메인 대화에 비밀 단어 `파랑고래`를 주고, 서브에이전트에게는 전달하지 않았다.
- 서브에이전트는 "알고 있는 비밀 단어는 없다"고 답했다.
- 한계: 이것은 "전달하지 않은 정보는 모른다"는 것을 보여 줄 뿐이다. 서브에이전트는 메인에서 넘겨 준 프롬프트만 본다는 구조를 확인한 정도이며, 강한 격리 증명은 아니다.

## 실험 C: 도구 제한 (`result-edit-attempt.md`)
- 메인이 reviewer에게 `phone.py`에 주석을 추가하라고 시켰다.
- 쓰기 도구가 없어서 수정하지 못했고, 파일은 그대로였다 (확인: 1번째 줄이 `import re`).
- 이것은 하네스 엔지니어링(5단계)의 첫 예: 지시문이 아니라 **도구 목록으로 능력을 막았다**.

## 결론
- 서브에이전트 = 역할, 도구 제한, 출력 형식을 가진 별도 작업자. 메인 컨텍스트를 오염시키지 않고 결과만 돌려준다.
- 각 실험 1회 실행. 리뷰 내용은 매번 달라질 수 있다.
