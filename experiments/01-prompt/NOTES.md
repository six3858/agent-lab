# 실험 01: 프롬프트 엔지니어링

같은 작업(전화번호 정규화)을 모호한 지시(A)와 구체적 지시(B)로 각각 `claude -p`에 실행. 깨끗한 폴더에서 실행해 `CLAUDE.md` 등 다른 컨텍스트는 섞이지 않음.

| 항목 | A (모호) | B (구체) |
|---|---|---|
| 응답 길이 | 91줄 | 46줄 |
| 요구 시그니처 `normalize_phone` | 모델이 임의 선택 (우연히 동일) | 지정대로 |
| 요청하지 않은 기능 | `clean_phone_list`, 중복 제거, 대표번호, `__main__` 데모 추가 | 없음 |
| 테스트 | 없음 (예상 출력 텍스트만) | pytest 13건 (정상 6 + 비정상 7) |
| 허용 범위 | 070, 지역번호, 1588 포함 (범위 확장) | 010, 02만 (명시한 범위) |
| 설명 분량 | 3줄 + 후속 제안 | 3줄 |
| 지시 준수 | 확인할 기준이 없음 | 형식, 3줄 제한, 표준 라이브러리 모두 준수 |

## 관찰
- 모호한 지시에서는 모델이 빈칸을 스스로 채워 **범위가 커지고** 검증 수단(테스트)이 빠졌다.
- 구체적 지시에서는 결과가 **검증 가능한 형태**로 나왔다. 길이도 절반.
- 검증: B의 코드와 테스트를 `sandbox/phone/`에 파일로 저장해 pytest 실행 → **13 passed**. (이 PC에는 pip/pytest가 없어 `ensurepip`로 pip를 먼저 설치함)
- 한계: 구체적 지시가 항상 정확성을 보장하는 것은 아니다. 이번에는 통과했지만 테스트로 확인했기 때문에 알 수 있었다.
