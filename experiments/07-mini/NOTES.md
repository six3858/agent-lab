# 실험 07: 에이전트 엔지니어링 (미니 프로젝트: 회의록 파이프라인)

1~6단계의 요소를 한 흐름으로 조합. 위치: `sandbox/mini/`

## 구성

| 요소 | 파일 | 1~6단계 대응 |
|---|---|---|
| 컨텍스트 | `CLAUDE.md` (산출물은 out/, 지어내지 말 것, 4섹션, 검수 필수) | 2단계 |
| 스킬(오케스트레이터) | `.claude/skills/meeting-pipeline/SKILL.md` (읽기 → 요약 저장 → 검수 → 1회 수정 → 보고) | 3단계 |
| 서브에이전트 | `.claude/agents/fact-checker.md` (읽기 전용, 원문과 요약 대조) | 4단계 |
| 하네스(훅) | `.claude/hooks/check_summary.py` (summary.md의 4섹션을 순서대로 검사, `out/hook.log` 기록) | 5단계 |
| 프롬프트 | 각 파일의 단계별 지시와 출력 형식 | 1단계 |
| 플러그인 | 이번에는 미사용 (6단계 방식으로 묶을 수 있음) | 6단계 |

## 실행
`sandbox/mini`에서 `claude -p "/meeting-pipeline meeting-raw.txt" --permission-mode acceptEdits` 1회.

원문은 함정을 넣어 두었다: 기한이 없는 할 일(정과장), 결론이 안 난 안건 2개, 다음 회의로 미룬 안건.

## 결과
- `out/summary.md` 생성, 4섹션 순서대로 존재.
- 훅 로그: `22:28:20 summary.md -> PASS` (저장 직후 자동 검사가 동작).
- fact-checker 판정: **통과**. 원문에 없는 내용, 누락, 틀린 담당자/날짜는 없다고 보고.
- 함정 처리: 정과장의 기한은 지어내지 않고 `미정`으로 썼다. (CLAUDE.md의 "지어내지 말 것" 규칙이 지켜짐)

## 발견한 문제 (이 실험의 가장 큰 배움)
1. **분류 오류가 통과됐다.** 요약의 "결정사항"에 "광고 예산 증액은 임원 보고 후 결정", "외주 업체 선정은 연기"가 들어 있다. 이들은 확정된 결정이 아니라 미해결 항목이고, "미해결 질문"에도 중복으로 들어 있다.
2. fact-checker는 이 문제를 **짚었지만 판정은 통과**로 냈다. 이유: 검수 기준을 "원문에 없는 내용 / 빠진 내용 / 틀린 담당자·날짜·수치"로만 정했기 때문에, "결정과 미해결의 분류"는 검수 항목이 아니었다. 파이프라인은 판정이 `수정 필요`일 때만 고치므로 수정 단계도 실행되지 않았다.
3. 교훈: **에이전트 시스템은 검수 기준에 없는 오류를 못 잡는다.** 개선하려면 fact-checker에 "결정사항에 미확정 항목이 들어 있지 않은가" 항목을 추가해야 한다.
4. 모델이 최종 보고 앞에 "지금은 fact-checker 검수가 끝나기를 기다리는 중입니다"라는 문장을 붙였다. 보고 자체는 정상이었다. 원인은 확인하지 못함.

## 한계
- 1회 실행. 응답은 매번 달라질 수 있다.
- 수정 경로(판정이 `수정 필요`일 때 요약을 고치는 단계)와 훅의 FAIL 경로는 이번 실행에서 발생하지 않아 검증하지 못했다.
- 훅은 형식(섹션 존재와 순서)만 검사한다. 내용의 정확성은 검사하지 못한다.

## 역할 분담 요약 (에이전트 엔지니어링의 핵심)
- 모델에게 맡기는 것: 이해, 요약, 판단
- 하네스가 강제하는 것: 형식, 저장 위치, 자동 검사
- 서브에이전트에게 분리하는 것: 검수 (작성자와 검수자를 분리)
- 사람이 정하는 것: 검수 기준 (기준 밖의 오류는 아무도 못 잡는다)
